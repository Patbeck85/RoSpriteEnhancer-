## 📜 Unbreakable Rules (The Hermes Creed)

### 1. Memory Management & Resource Safety

#### LockBits Protection Rule
- **Requirement:** Every `Bitmap.LockBits` MUST release its bits in a `finally` block (`UnlockBits`)
- **Purpose:** Prevent native memory leaks when processing thousands of sprites in batch mode
- **Violation Consequence:** Windows Runtime Crash after processing ~10,000 sprites
- **Implementation Pattern:**
```csharp
using (var bitmap = new Bitmap(filePath))
{
    var bits = bitmap.LockBits(
        new Rectangle(0, 0, bitmap.Width, bitmap.Height),
        ImageLockMode.WriteOnly,
        PixelFormat.Format24bppRgb
    );
    
    try
    {
        // Process bitmap data
    }
    finally
    {
        bitmap.UnlockBits(bits); // ALWAYS call this
    }
}
```

#### Consistent IDisposable Cleanup Rule
- **Requirement:** Intermediate bitmaps (`preScaled`, `scaled`, `shaded`, temporary buffers) MUST be disposed immediately after use
- **Purpose:** Prevent memory accumulation during long batch operations
- **Implementation Pattern:**
```csharp
using (var preScaled = new Bitmap(targetWidth, targetHeight, PixelFormat.Format32bppPArgb))
{
    // Process...
} // Automatically disposed when scope exits
```

#### Preview Loop Cleanup Rule
- **Requirement:** Preview timers and SPR animations MUST dispose old bitmap resources before loading new frames
- **Purpose:** Prevent memory leaks in long-running preview sessions
- **Implementation Pattern:**
```csharp
private Bitmap currentPreviewBitmap = null;

private void UpdatePreview()
{
    if (currentPreviewBitmap != null)
    {
        currentPreviewBitmap.Dispose(); // Clean up old bitmap
        currentPreviewBitmap = null;
    }
    
    // Load new frame...
}
```

### 2. Thread Safety & UI Isolation

#### WPF Dispatcher Compliance Rule
- **Requirement:** Background threads (`Parallel.ForEachAsync`, Worker Tasks) MUST NEVER access WPF elements directly
- **Purpose:** Prevent cross-thread operation exceptions and UI corruption
- **Implementation Pattern:**
```csharp
// ❌ WRONG - Direct WPF access from background thread
progressBar.Value = 50;

// ✅ CORRECT - Dispatcher.InvokeAsync
Dispatcher.InvokeAsync(() =>
{
    progressBar.Value = 50;
});
```

#### CancellationToken Respect Rule
- **Requirement:** All loops and async operations MUST check `CancellationToken` regularly
- **Purpose:** Enable clean cancellation of long-running operations
- **Implementation Pattern:**
```csharp
for (int i = 0; i < items.Count && !cancellationToken.IsCancellationRequested; i++)
{
    // Process item...
}
```

### 3. Ragnarok Online Client Compatibility

#### EUC-KR Encoding Rule
- **Requirement:** GRF paths and folder names MUST always be in EUC-KR encoded/decoded
- **Purpose:** Ensure compatibility with RO client's file system expectations
- **Implementation Pattern:**
```csharp
string eucKrPath = Encoding.GetEncoding("euc-kr")
    .GetBytes(utf8Path)[0] // Simplified example
    .ToString();
```

#### Magenta Colorkey Invariance Rule
- **Requirement:** RO BMPs use `#FF00FF` (Slot 0) as transparency
- **Purpose:** Maintain client's color-key transparency system
- **Implementation Pattern:**
```csharp
// Convert Magenta to Alpha during processing
byte[] alphaData = ConvertMagentaToAlpha(pixelData);

// Convert Alpha back to Magenta on export
byte[] pixelData = ConvertAlphaToMagenta(alphaData);
```

#### ACT Anchor Scaling Rule
- **Requirement:** When scaling SPR frames, offsets in associated `.act` files MUST be scaled proportionally
- **Purpose:** Prevent sprite misalignment in game client
- **Formula:** `New_Offset = Original_Offset * (New_Width / Original_Width)`
- **Implementation Pattern:**
```csharp
float scale = newWidth / originalWidth;
newActFile.OffsetX = (int)(originalActFile.OffsetX * scale);
newActFile.OffsetY = (int)(originalActFile.OffsetY * scale);
```

#### Error Tolerance Rule
- **Requirement:** Faulty individual files or external tools (ESRGAN) MUST NEVER stop entire batch run
- **Purpose:** Ensure robustness against corrupted assets
- **Implementation Pattern:**
```csharp
try
{
    // Process file...
}
catch (Exception ex)
{
    Log.Error($"Failed to process {filePath}: {ex.Message}");
    continue; // Skip to next file
}
```
