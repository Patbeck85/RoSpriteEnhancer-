* `GrfArchive.cs`: GRF v2.0 Archive Reader, Extractor, Packer & Merger (Zlib/Deflate).
* `SprReader.cs` & `SprWriter.cs`: Binary SPR Parser/Encoder (v1.1 - v2.1) mit RLE-Handling & Palette-Generator.

* `BatchProcessor.cs`: Multithreaded Batch Queue (`Parallel.ForEachAsync`) mit Ausreißer-Analyse.
* `IncrementalManifest.cs`: Inkrementelles Caching via MD5-Hashes.
* `XbrzScaler.cs` & `Scale2x.cs`: Pure C# Pixel-Art Scaler.
* `SuperSampler.cs`: Super-Sampling Anti-Aliasing (Lanczos3, Bicubic, Bilinear Downscaler).
* `PixelEnhancer.cs`: Pixel-Shading (Outline-Dilate, Drop-Shadow, Highlight-Boost, Sharpen, HSL Shift).
* `PaletteQuantizer.cs` & `MagentaHandler.cs`: Median-Cut 8-bit Quantisierer & Colorkey-Erkennung (`#FF00FF`).
* `SpriteFilter.cs`: EUC-KR Pfad-Segment Matching für RO-Kategorien (Monster, Jobs, Homunculi, etc.).
* `PresetManager.cs`: JSON-Preset I/O unter `%AppData%\RoSpriteEnhancer\Presets\`.
* `EsrganRunner.cs`: External CLI Process Wrapper mit Semaphore Concurrency Protection (`ConcurrencyLimit = 1`).

## 2. DOMAIN LAWS & TECHNICAL CONSTRAINTS

### SPRITE-001 — Transparency & Colorkey Integrity
1. **Magenta Colorkey (`#FF00FF`):** In BMP-Sprites entspricht Index 0 / `#FF00FF` der Transparenz. Konvertierung muss strikt über `MagentaHandler.MagentaToAlpha` vor dem Scaling und `AlphaToMagenta` nach dem Shading erfolgen.
2. **ACT Alignment:** Beim Skalieren von `.spr`-Dateien muss die zugehörige `.act`-Datei bei aktiviertem `ScaleActAnchors` über `ActFile.TryScaleOffsets` mit demselben Skalierungsfaktor angepasst werden, damit Sprite-Ankerpunkte nicht verrutschen.

### SPRITE-002 — Threading & Memory Protection (`MEMORY-001`, `THREAD-001`)
1. **Bitmaps Disposing:** Jedes temporäre `System.Drawing.Bitmap` muss sofort verworfen werden (`using` oder explizites `.Dispose()`).
2. **Parallel.ForEachAsync Safety:** Der Batch-Prozess läuft entkoppelt vom UI-Thread. Fortschritts-Meldungen dürfen UI-Elemente nur über `Dispatcher.InvokeAsync` aktualisieren.
3. **Unsafe Memory Blocks:** Pixel-Operationen nutzen `LockBits` / `Marshal.Copy` oder `unsafe`-Zeiger für maximale Geschwindigkeit. Memory Leaks in unmanaged Pointern sind strikt verboten.

## 3. HERMES RUNTIME EXECUTION OVERRIDES

1. **Build Directive:** Builds erfolgen über `dotnet build RoSpriteEnhancer.csproj` oder `dotnet publish -c Release -r win-x86 --self-contained true`.
2. **Test Isolation:** Neue Unit-Tests werden unter `tests/Unit/` abgelegt. Output geht nach `.workspace_temp/logs/`.
3. **No Breaking Refactors:** Die bestehenden Klassen in `RoSpriteEnhancer.Core/` dürfen nicht grundlos umbenannt werden, um Rückwärtskompatibilität zu wahren.

### HERMES-STRICT-YOLO — Uninterrupted Execution Chain
1. **No Conversational Check-ins:** Nach Abschluss eines Tasks (z. B. Task-0001) ist es STRENGSTENS VERBOTEN, Sätze wie "Soll ich fortfahren?", "Möchtest du, dass ich X tue?" oder "Warte auf deine Bestätigung" auszugeben.
2. **Immediate Task Chaining:** Sobald ein Task im Status `CLOSED` ist, MUSS der zuständige Agent UNVERZÜGLICH und im SELBEN Turn den nächsten Task aus `ROADMAP.md` auf `IN_PROGRESS` setzen und die Werkzeuge (Terminal/Code-Editor) abfeuern.
3. **Execution Termination Criteria:** Der Agent darf die Schleife AUSSCHLIESSLICH unterbrechen bei:
   - Einem kritischen S1-Fehler (`FAILURE-001`), der nach 3 Self-Healing Versuchen fehlschlägt.
   - Wenn ALLE Tasks in `ROADMAP.md` auf `CLOSED` stehen.
